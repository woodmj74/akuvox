# Akuvox SmartPlus Development Notes

Last updated: 2 July 2026

## Project context

This fork adds automatic rotating-token support to the Akuvox SmartPlus Home
Assistant custom integration.

The working deployment uses a dedicated tenant/family SmartPlus account which
has permission to operate the required gates. Home Assistant must be the only
active client for that account. Do not sign the account into another SmartPlus
installation after Home Assistant takes ownership of the session.

The normal phone can continue using a separate primary SmartPlus account.

## Akuvox token protocol

An initial SmartPlus capture must provide:

- `auth_token`
- `token` (the current API access token)
- `refresh_token`

Refresh request:

```http
POST https://gate.{subdomain}.akuvox.com:8600/refresh_token
Content-Type: application/json
Accept: application/json
api-version: 6.8
x-auth-token: CURRENT_ACCESS_TOKEN

{"refresh_token":"CURRENT_REFRESH_TOKEN"}
```

Successful response:

```json
{
  "datas": {
    "token": "NEW_ACCESS_TOKEN",
    "refresh_token": "NEW_REFRESH_TOKEN",
    "token_valid": "604800"
  },
  "err_code": "0",
  "message": "success"
}
```

Both returned tokens rotate. They must be replaced and persisted together.
`auth_token` does not rotate in this flow.

HTTP/1.1 works. The important application protocol version is `6.8`.

## Refresh lifecycle

- `token_valid=604800` means the access token is valid for seven days.
- The integration stores an absolute `token_expires_at` timestamp.
- It refreshes one day early, so a new token logs a schedule of about 144 hours.
- Restarting Home Assistant reloads the persisted timestamp; restart does not
  reset the seven-day clock.
- The access and refresh tokens are saved in one Home Assistant storage write,
  under a per-config-entry storage key.
- An `asyncio.Lock` prevents concurrent requests from consuming a rotating
  refresh token more than once.
- A refresh with an uncertain network result is not blindly retried.
- Definitive refresh failure initiates Home Assistant reauthentication.
- The scheduler is a Home Assistant background task and does not block startup.

Do not manually edit files under Home Assistant's `.storage` directory.

## Live validation completed

Live ecloud testing on 1 July 2026 confirmed:

1. Initial captured token pair was rotated successfully.
2. The returned replacement pair passed a `userconf` request.
3. A second manual rotation also succeeded.
4. The second replacement pair passed `userconf`.
5. Gate relay operations succeeded after the second rotation.
6. The replacement session survived Home Assistant restart.

## Door-event polling

`akuvox_door_update` is generated by polling Akuvox's door activity endpoint.
Possible payload fields include:

- `CaptureTime`
- `CaptureType`
- `Initiator`
- `Location`
- `MAC`
- `Relay`
- `PicUrl`

The tested tenant account received HTTP 429 from this endpoint and produced no
events. Door-event polling can therefore be disabled under Akuvox Configure.
Disabling it does not affect:

- gate relay buttons;
- cameras;
- temporary-key sensors;
- token refresh.

When enabled, polling uses a 30-second normal interval and exponential
rate-limit backoff up to one hour.

## Other compatibility fixes

- Door buttons resolve the current client token instead of caching the initial
  token.
- Generic camera configuration contains both legacy and current Home Assistant
  layouts. The current layout requires an `advanced` section.
- The camera feed has been observed working. Transient go2rtc/FFmpeg messages
  are separate from token refresh.
- The Options flow uses Home Assistant-compatible config-entry storage.
- The `akuvox.refresh_tokens` action uses an Akuvox config-entry selector.
- Repetitive HTTP 429 details are suppressed while rate-limit backoff is active.

## Debugging

Enable debug logging from:

**Settings → Devices & services → Akuvox SmartPlus → Enable debug logging**

Expected successful rotation messages:

```text
Starting Akuvox token refresh for subdomain=...
Akuvox token pair rotated and persisted (...fingerprints only...)
Akuvox refreshed session validated with userconf
Akuvox token refresh scheduled in 144.0 hours
```

Fingerprints are short SHA-256 identifiers, not token prefixes.

For a controlled rotation, run the `akuvox.refresh_tokens` action and select
the Akuvox config entry. Do not repeatedly invoke it without a reason.

## Deployment

The source folder is:

```text
custom_components/akuvox
```

Copy that folder to the Home Assistant server as:

```text
/config/custom_components/akuvox
```

The server must contain `/config/custom_components/akuvox/manifest.json`
directly; avoid an extra nested `akuvox/akuvox` directory.

After copying updated code, restart Home Assistant. Rotating tokens are stored
by Home Assistant and normally survive code updates and restarts.
